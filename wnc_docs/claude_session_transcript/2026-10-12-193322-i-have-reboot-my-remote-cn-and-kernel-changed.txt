● The first line of the full log shows the cause:

  insmod: ERROR: could not insert module .../gtp5g/gtp5g.ko: Invalid module 
  format

  What happened. run_free5gc tries to load the gtp5g kernel module from
  gtp5g/gtp5g.ko, and the kernel refused it with "Invalid module format". The
  kernel gives this error when a .ko file was built for a different kernel
  version than the one running. The most likely cause is that the reboot started
  a newer kernel, for example after a package update installed one. The old
  gtp5g.ko is still built for the previous kernel.

  The UPF error follows from that. The module did not load, so no kernel module
  registered the gtp5g link type. When the UPF asked the kernel to create the
  gtp5g network interface, the kernel answered "operation not supported".

  mongo: command not found can be ignored. run.sh:135 calls the old mongo shell
  first and then calls mongosh. The true printed after it is the output of
  mongosh, so the database cleanup did run.

  How to fix it. Run these on the CN machine:

  # 1. Compare the running kernel with the kernel the .ko was built for
  uname -r
  modinfo /home/wnc/Downloads/free5gc_use_open5gs_ipv6/gtp5g/gtp5g.ko | grep
  vermagic

  # 2. If the two versions differ, make sure headers for the running kernel 
  exist
  ls /lib/modules/$(uname -r)/build

  # 3. Rebuild gtp5g against the running kernel
  cd /home/wnc/Downloads/free5gc_use_open5gs_ipv6/gtp5g
  make clean && make

  # 4. Load it with the IPv6 data path turned on, then check that it loaded
  insmod gtp5g.ko ipv6_data_path=1
  cat /sys/module/gtp5g/parameters/ipv6_data_path    # should print Y
  dmesg | grep -i gtp5g | tail -5

  If step 2 shows that the build directory is missing, install the kernel
  headers before step 3. On a RHEL-family system, which the [root@...] prompt
  suggests, the command is dnf install kernel-devel-$(uname -r). On Ubuntu it is
  apt install linux-headers-$(uname -r).

  ipv6_data_path=1 matters for your IPv6 work. The gtp5g module turns the IPv6
  data path off by default. If run_free5gc runs insmod without this parameter,
  the UPF will report no IPv6 support even after the rebuild. Check how the
  run_free5gc alias calls insmod with type run_free5gc on CN.

  After the module loads, run run_free5gc again. If the module is already
  loaded, its insmod will fail with "File exists", and that error is harmless.

  ★ Insight ─────────────────────────────────────
  - A kernel module stores the kernel version it was built for in a "vermagic"
    string. The kernel refuses to load a module whose vermagic does not match
    the running kernel, which is the "Invalid module format" error above. That
    is why every kernel upgrade breaks a module built by hand with make.
  - The gtp5g README describes DKMS support, a system that rebuilds out-of-tree
    modules automatically when a new kernel is installed. Setting it up would
    stop this failure from coming back after the next kernel update.
    ─────────────────────────────────────────────────

  Paste the output of steps 1 and 2 if the rebuild fails or the versions turn
  out to match.

  Your old gtp5g.ko did not match the running kernel. The Invalid module format

  1. The kernel changed at the reboot. A package update may have installed a

     machine together with the source. A reboot clears the module from memory.

  read-only.

  # Kernel version of the current boot and of the boot before it
  uname -r

  A kernel installed after your last successful start before the reboot points
  to case 1.

● Ubuntu boots the kernel that GRUB (the boot loader) selects. The GRUB_DEFAULT
  line in /etc/default/grub controls that choice. Its usual value is 0, which
  means "the first menu entry". The first entry always points to the newest
  installed kernel, so each reboot after an apt kernel update starts the new
  kernel. That is what happened today.

  To make GRUB always boot one specific kernel, run these on CN:

  1. Check the current setting and the exact menu entry names (read-only):

  grep ^GRUB_DEFAULT /etc/default/grub
  grep -E "^\s*(submenu|menuentry) '" /boot/grub/grub.cfg | cut -d"'" -f2

  The second command should list names like Advanced options for Ubuntu and
  Ubuntu, with Linux 5.15.0-198-generic. GRUB needs these exact names.

  2. Set GRUB_DEFAULT to the kernel you want. This command rewrites only the
  GRUB_DEFAULT= line in /etc/default/grub. The example uses 5.15.0-198, which is
  the kernel your rebuilt gtp5g.ko matches:

  sed -i 's/^GRUB_DEFAULT=.*/GRUB_DEFAULT="Advanced options for Ubuntu>Ubuntu, 
  with Linux 5.15.0-198-generic"/' /etc/default/grub

  The > separates the submenu name from the entry name inside that submenu. Copy
  both names exactly from the output of step 1.

  3. Regenerate GRUB's menu file so the setting takes effect:

  update-grub

  4. Verify:

  grep ^GRUB_DEFAULT /etc/default/grub

  There are two limits to keep in mind.

  - The pin does not stop apt from installing new kernels. It only stops GRUB
    from booting them by default. When apt installs a newer kernel, it removes
    older ones it no longer needs. Today it removed -194 in that way. apt does
    not remove the kernel that is currently running, so -198 is safe while the
    machine runs on it. If -198 were ever removed, the pinned entry would no
    longer exist, and GRUB would fall back to the first entry, which is the
    newest kernel. To fully freeze the kernel, also run apt-mark hold 
    linux-generic linux-image-generic linux-headers-generic, as I mentioned
    earlier. The cost is that the machine stops receiving kernel security fixes.
  - To try a newer kernel once without changing the default, set
    GRUB_DEFAULT=saved in place of the fixed name, run update-grub, and use
    grub-set-default "<name>" for the normal kernel and grub-reboot "<name>" for
    a single boot. Skip this if you only want one fixed kernel.

  version stored inside gtp5g.ko (its vermagic) and compares it with the running
  kernel (uname -r). If the two differ, it prints which kernel each one is,

  run_free5gc(){
      local gtp5g_ko=/home/wnc/Downloads/free5gc_use_open5gs_ipv6/gtp5g/gtp5g.ko
      local running_kernel=$(uname -r)
      if [ ! -f "$gtp5g_ko" ]; then
          echo "run_free5gc: $gtp5g_ko does not exist. Build gtp5g first:"
          echo "    cd $(dirname "$gtp5g_ko") && make clean && make"
          return 1
      fi
      local built_kernel=$(modinfo -F vermagic "$gtp5g_ko" | awk '{print $1}')
      if [ "$built_kernel" != "$running_kernel" ]; then
          echo "run_free5gc: gtp5g.ko was built for kernel $built_kernel, but
  the running kernel is $running_kernel."
          echo "Rebuild gtp5g first:"
          echo "    cd $(dirname "$gtp5g_ko") && make clean && make"
          return 1
      fi
      insmod "$gtp5g_ko" ipv6_data_path=1
      /home/wnc/Downloads/free5gc_$free5gc_ver/free5gc/run.sh -cp -dp 2>&1 | tee
  /home/wnc/Downloads/free5gc_$free5gc_ver/free5gc/log/console_free5gc.log
  }

**The detail spec/procedure 4.2.2 Npcf_AMPolicyControl_Create Service Operation** 

Npcf_AMPolicyControl_Create Service Operation
The Npcf_AMPolicyControl_Create service operation is initiated by a Network Function (NF) service consumer, like an Access and Mobility Management Function (AMF), to create an Access and Mobility (AM) Policy Association for a User Equipment (UE). This typically happens when the UE registers with the network or when the AMF is relocated and a new Policy Control Function (PCF) is selected. This operation is not applicable for emergency registered UEs.

To create the policy association, the NF service consumer sends an HTTP POST request to the PCF. The request body contains various details about the UE and its connection, including:

SUPI (Subscription Permanent Identifier) 
Notification URI 
Access Type 
PEI (Permanent Equipment Identifier) 
User Location Information 
UE Time Zone 
Serving PLMN/SNPN Identifier 
RAT Type 
Subscribed 
UE-AMBR 

Upon receiving the request, the PCF:
Assigns a policy association ID.
Determines the applicable policies.
Sends a "201 Created" HTTP response with the location of the newly created resource and a response body containing the policy details.

The response from the PCF may include:
Service Area Restrictions 
RAT Frequency Selection Priority (RFSP) Index 
Authorized UE-AMBR 
Authorized UE-Slice-MBR(s) 
Policy Control Request Triggers such as location change or change of allowed NSSAI.

**The detail spec/procedure 4.2.2 Npcf_UEPolicyControl_Create Service Operation.**

Npcf_UEPolicyControl_Create Service Operation
The Npcf_UEPolicyControl_Create service operation is used to establish a UE Policy Association. This is typically done by an NF service consumer (such as an AMF) in several scenarios:

During the UE's initial registration to the network.
When a UE in single-registration mode moves from S1 mode to N1 mode, and no policy association exists.
When the AMF is relocated and a new PCF is selected.
To support the delivery of URSP in EPS.
The creation of a UE policy association only applies to normally registered UEs and not for emergency registered ones.
To create the association, the NF service consumer sends an HTTP POST request to the PCF. This request includes information such as:

SUPI (Subscription Permanent Identifier) 
Notification URI 
Access Type 
PEI (Permanent Equipment Identifier) 
User Location Information 
UE Time Zone 
Serving PLMN/SNPN Identifier 
RAT Type 
PC5 capability for V2X 
5G ProSe capability 

Upon a successful request, the PCF will:
Assign a UE policy association ID.
Determine the applicable UE policy.
If necessary, provision the UE policy using the Namf_Communication service.
Respond with a "201 Created" HTTP message, which includes the location of the new resource and a response body with the negotiated features and other optional information.

The response may also contain Policy Control Request Triggers, which are events that would require the NF service consumer to contact the PCF again for policy updates. Examples include changes in location, PLMN, or UE connectivity state.
